## 0. 本文用途

本文只负责把目标电脑准备到“可以开发和运行默认 CLI 链路”的状态。部署完成后转到 `docs\01_Codex开发执行文档..md`。

本指南采用以下最小原则：

- 只部署 AMD 基线和默认 `Hy-MT2 7B + GPU`；
- 1.8B 是可选轻量模型，不阻塞首版开发；
- 部署阶段只做组件可用性冒烟，不重复实现业务管线；
- 模型功能联调、英语/日语端到端和实时测试放在 CLI 的 G1/G2；
- 环境未变化时，不重复安装、下载、全量哈希或四组合测试。

本文所有命令块均在 Windows **命令提示符（CMD）** 中逐行执行。`^` 是 CMD 的续行符，后面不要留空格；每次重新打开 CMD，先执行第 3 节的会话变量命令。这里使用项目内 Python `.venv`，不需要激活环境。

如果部署日期明显晚于版本基线，先通过本文末尾官方链接核对完整 AMD 组合。只有兼容矩阵发生变化时才整体更新版本，不混装不同 ROCm 代际的 wheel 或 DLL。

## 2. 系统前提

### 2.1 Windows 与显卡驱动

确认 Windows 11 x64、Windows Update 已完成，并安装 AMD 官方兼容驱动。版本基线文档原记录为 Windows 11 25H2、Adrenalin 26.8.1 WHQL；更晚部署时应以 AMD 官方兼容矩阵为准。

重启后检查：

```bat
pnputil /enum-devices /connected /class Display /drivers
```

必须能看到 RX 9070 XT，并核对显示驱动版本。不要安装 NVIDIA CUDA Toolkit，也不要使用第三方修改版显卡驱动。

### 2.2 基础工具

以管理员身份打开 CMD，安装一次：

```bat
winget install --exact --id Python.Python.3.12
winget install --exact --id Git.Git
winget install --exact --id Microsoft.VCRedist.2015+.x64
```

重新打开普通 CMD：

```bat
py -3.12 --version
git --version
```

后续直接调用虚拟环境解释器，不要求激活虚拟环境。

## 4. Python、ROCm 与项目依赖

### 4.1 创建虚拟环境

```bat
py -3.12 -m venv "%ProjectRoot%\.venv"
"%Python%" -m pip install --upgrade pip setuptools wheel
```

这里继续使用 `.venv`：项目的 AMD Python 依赖由 pip wheel 安装，FFmpeg 和 llama.cpp/ROCm 运行时另行放在项目目录，安装器与 CLI 也都按 `.venv` 路径设计。引入 Miniconda 不会替代这些步骤，反而会增加安装器前提和环境维护工作。开源发布时交付依赖清单与安装步骤，不把本机 `.venv` 打包进源码仓库。

### 4.2 安装 AMD 官方组合

RX 9070 XT 的目标为 `gfx1201`。按本文版本基线安装：

```bat
"%Python%" -m pip install ^
  --index-url https://stable.repo.amd.com/rocm/whl-next/ ^
  "rocm[libraries,device-gfx1201]==10.0.0"

"%Python%" -m pip install ^
  --index-url https://stable.repo.amd.com/rocm/whl-next/ ^
  "torch[device-gfx1201]==2.12.0+rocm10.0.0" ^
  "torchvision[device-gfx1201]==0.27.0+rocm10.0.0" ^
  "torchaudio==2.11.0+rocm10.0.0"
```

不要单独替换其中一个 torch 包。版本组合更新时应按 AMD 选择器整体更新。

### 4.3 安装项目依赖

```bat
"%Python%" -m pip install ^
  "transformers==5.13.1" ^
  accelerate ^
  "huggingface_hub[cli]" ^
  "wtpsplit[onnx-cpu]==2.2.1" ^
  "silero-vad[onnx-cpu]==6.2.1" ^
  soundfile ^
  librosa ^
  nagisa ^
  httpx ^
  psutil ^
  pytest
```

不安装 vLLM、FlashAttention 或另一来源的 PyTorch。随后只做一次依赖和 GPU 身份检查：

```bat
"%Python%" -m pip check
"%Python%" -c "import torch; print(torch.__version__); print('hip:', torch.version.hip); print('available:', torch.cuda.is_available()); print('device:', torch.cuda.get_device_name(0)); x=torch.randn((1024,1024),device='cuda:0',dtype=torch.float16); print((x@x).mean().item())"
```

必须满足 HIP 非空、GPU 可用、设备名正确且 FP16 运算成功。这里的 `cuda:0` 是 PyTorch 在 HIP 上的兼容 API。

## 6. 安装项目内 FFmpeg

使用 FFmpeg 官方下载页列出的 Windows 构建来源。以下命令沿用已核对的 gyan.dev essentials 包：

```bat
set "FfmpegZip=%ProjectRoot%\tools\downloads\ffmpeg-release-essentials.zip"
set "FfmpegExtract=%ProjectRoot%\tools\downloads\ffmpeg-extracted"
if not exist "%FfmpegExtract%" mkdir "%FfmpegExtract%"

curl.exe --fail --location --retry 3 --output "%FfmpegZip%" ^
  "https://www.gyan.dev/ffmpeg/builds/ffmpeg-release-essentials.zip"

tar.exe -xf "%FfmpegZip%" -C "%FfmpegExtract%"
for /r "%FfmpegExtract%" %F in (ffmpeg.exe) do @copy /Y "%F" "%Ffmpeg%"
if not exist "%Ffmpeg%" echo ffmpeg.exe not found after extraction
```

上面的 `for` 使用 CMD 交互窗口语法；若写入 `.cmd` 脚本，应把 `%F` 改成 `%%F`。

验证一次：

```bat
"%Ffmpeg%" -hide_banner -version
"%Ffmpeg%" -hide_banner -devices
"%Ffmpeg%" -hide_banner -filters | findstr /C:"aresample"
```

输出需要包含 DirectShow/dshow 和 `aresample`。后者用于让离线 PCM 样本计数保持与视频时间戳一致，不是音质增强功能。

## 7. 安装 llama.cpp ROCm 运行时

Python ROCm 10.0 留在 `.venv`；llama.cpp 所需 ROCm 7.14.1 放在 `tools\rocm-7.14`。两者运行在不同进程，不向系统 PATH 写入任何一个版本。

### 7.1 本地 ROCm 运行时

```bat
set "RocmRuntime=%ProjectRoot%\tools\rocm-7.14"
set "RocmMulti=%ProjectRoot%\tools\downloads\therock-windows-multiarch-7.14.1.tar.gz"
set "RocmGfx=%ProjectRoot%\tools\downloads\therock-windows-gfx120X-7.14.1.tar.gz"

curl.exe --fail --location --retry 3 --output "%RocmMulti%" ^
  "https://repo.amd.com/rocm/tarball-multi-arch/therock-dist-windows-multiarch-7.14.1.tar.gz"

curl.exe --fail --location --retry 3 --output "%RocmGfx%" ^
  "https://repo.amd.com/rocm/tarball-multi-arch/therock-dist-windows-gfx120X-all-7.14.1.tar.gz"

tar.exe -xzf "%RocmMulti%" -C "%RocmRuntime%" --strip-components=1
tar.exe -xzf "%RocmGfx%" -C "%RocmRuntime%" --strip-components=1
```

两个归档解压到同一目录。

### 7.2 固定 llama.cpp 构建

沿用已核对的 `b10708`：

```bat
set "LlamaBuild=b10708"
set "LlamaAssetName=llama-%LlamaBuild%-bin-win-rocm-7.14-x64.zip"
set "LlamaZip=%ProjectRoot%\tools\downloads\%LlamaAssetName%"
set "ExpectedLlamaSha256=06DF59F99DA7A15398EB3BE55EA6D05C9F7E269318E950886E7A26B012FDF746"

curl.exe --fail --location --retry 3 --output "%LlamaZip%" ^
  "https://github.com/ggml-org/llama.cpp/releases/download/%LlamaBuild%/%LlamaAssetName%"

"%Python%" -c "import hashlib,sys; actual=hashlib.file_digest(open(sys.argv[1],'rb'),'sha256').hexdigest(); print('SHA-256:',actual); sys.exit(0 if actual.lower()==sys.argv[2].lower() else 1)" "%LlamaZip%" "%ExpectedLlamaSha256%" && tar.exe -xf "%LlamaZip%" -C "%ProjectRoot%\tools\llama.cpp-hip"
```

只有哈希一致才会解压；若校验不一致，停止部署并重新检查下载文件。临时检查设备，随后恢复当前 CMD 的 PATH：

```bat
set "OriginalPath=%PATH%"
set "PATH=%LlamaRuntimeEntries%;%OriginalPath%"
"%LlamaServer%" --version
"%LlamaServer%" --list-devices
set "PATH=%OriginalPath%"
```

必须看到 RX 9070 XT 和 ROCm/HIP 后端。不要把 ROCm 10 DLL 复制到 llama.cpp 目录。

## 8. 系统音频回环

枚举现有设备：

```bat
"%Ffmpeg%" -hide_banner -list_devices true -f dshow -i dummy
```

优先使用已有“立体声混音 / Stereo Mix”或 `virtual-audio-capturer`。没有可用回环设备时，按 [virtual-audio-capturer 项目说明](https://github.com/rdp/virtual-audio-capture-grabber-device) 安装后再用 FFmpeg 实测，不能只看设备管理器。

采集 10 秒：

```bat
set "AudioDevice=virtual-audio-capturer"

"%Ffmpeg%" -hide_banner ^
  -f dshow ^
  -i "audio=%AudioDevice%" ^
  -t 10 ^
  -ac 1 ^
  -ar 16000 ^
  "%ProjectRoot%\testdata\loopback-smoke.wav"
```

确认 WAV 可播放且不是全静音。失败时可以继续开发离线链路，但实时 G2 暂不具备前提。

## 9. 一次性部署冒烟

部署阶段只做以下项目：

1. `pip check` 和 AMD HIP FP16 运算已通过；
2. FFmpeg 能启动并包含 dshow 和 `aresample`；
3. llama-server 能列出 RX 9070 XT；
4. Silero、Smart Turn、SaT ONNX 与本地 tokenizer 能加载；

## 12. 常见错误的最短处理

- **`torch.version.hip` 为 `None`**：检查是否被 CPU/NVIDIA wheel 替换，重新安装第 4.2 节完整 AMD 组合。
- **llama-server 缺少 DLL**：确认 ROCm 7.14 的 multiarch 和 gfx120X 归档解压到同一目录，并只在 llama 子进程 PATH 中使用。
- **llama-server 只显示 CPU**：确认下载资产名包含 `win-rocm-7.14-x64` 且存在 `ggml-hip.dll`。
- **Hugging Face 下载中断**：原样重跑相同命令，不删除已完成分片。
- **日语对齐缺少分词依赖**：确认项目 `.venv` 中已安装 `nagisa`。
- **7B GPU OOM**：关闭其他显存占用后重试一次；仍失败则记录证据并请用户决定是否使用 7B CPU。7B 仍是默认部署模型，不得静默改成 1.8B 或改造调度框架。
